# M8 quiet signals (development, not shipped)

## Scope — 2026-10-04

Starts from main `8f1d8e4`, after [M7 PR #16](https://github.com/boorkymoorky/molaway/pull/16) merged and [main verification](https://github.com/boorkymoorky/molaway/actions/runs/37213893543) passed. M8 evaluates four signals within the existing sandbox and public APIs. M9 and release publishing are outside this change. Windows PR #2 and unfinished local Windows changes remain separate. M6 structured physical checks remain deferred; daily-use feedback continues.

## Supported scope and explicit deferrals

| Signal | M8 decision | Limits |
| --- | --- | --- |
| Microphone use | Implement **audio input in use**, off by default. Read only Core Audio's process input-stream running flags. | Covers microphones and virtual audio input; does not identify a microphone, a meeting, speech, muting, or a person's presence. Microphone-only classification is deferred. A running duplex device alone is insufficient evidence because it could be playing output only. |
| Screen sharing | Defer automatic detection; retain manual Presentation mode. | The public APIs reviewed did not establish a reliable system-wide flag for other apps' active sharing within these permissions. ScreenCaptureKit manages capture streams and shareable content; it is not evidence that another app is sharing. No capture stream, window-list heuristic, UI scraping or private API is added. |
| Full screen | Implement the active app's native macOS full-screen presentation flag, off by default. | Uses only `.fullScreen`, not hidden Dock/menu flags or window dimensions. Maximized windows, borderless games, other displays and universal full-screen detection are deferred. |
| Selected apps | Implement an explicit local list, off by default and initially empty. Match only the exact frontmost app bundle identifier. | Background apps, helper processes, websites and document/window identity are not inferred. A missing/invalid identifier gives unavailable status. An empty list never quiets alerts. |

Apple references: [Core Audio input-running property](https://developer.apple.com/documentation/coreaudio/kaudioprocesspropertyisrunninginput), [process object list](https://developer.apple.com/documentation/coreaudio/kaudiohardwarepropertyprocessobjectlist), [system presentation options](https://developer.apple.com/documentation/appkit/nsapplication/currentsystempresentationoptions), [full-screen support](https://developer.apple.com/library/archive/documentation/General/Conceptual/MOSXAppProgrammingGuide/FullScreenApp/FullScreenApp.html), [frontmost application](https://developer.apple.com/documentation/appkit/nsworkspace/frontmostapplication), and [ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit). The SDK's public `AudioHardware.h` describes the input-running property as active input streams, whereas device-running state can include output. The screen-sharing deferral is a scoped engineering decision from these APIs, not a claim about every future macOS API.

## Behavior and privacy

- All three new signals only quiet alerts and app sounds through the existing Smart Pause decision. They do not keep counting during inactivity, stop accrued work, count a break, advance cadence, or increment snoozes. Existing camera, video, Watching, shared Focus, typing, manual pause, Office Hours and sleep/lock behavior remains intact. Watching is still available when input-free activity should keep counting.
- Enabled signals are sampled with the existing five-second sensor poll; transitions can take up to a poll interval to appear. Preference edits refresh immediately. Sleep/lock clears the M8 snapshot; wake requests a fresh sample. Unavailable readings provide no new quiet reason. After the last quiet reason ends, the existing 60-second return interval holds a pending reminder. An unavailable reading ending a prior quiet period also retains that interval.
- Audio queries are size-bounded and use only returned object entries. Failures, changed/invalid sizes and invalid running values become unavailable; any positively observed active input wins over partial unavailable results. No IO procedure, process tap, audio engine or recording is started. No PID, audio-process bundle identity, device name or content is read. Transient object IDs are discarded after each query.
- The selected list is limited to 32 unique bundle identifiers, each at most 255 ASCII bytes. Malformed, duplicate, oversized or wrong-type imported selections are rejected. The explicit picker reads only app metadata and never loads or launches its executable. It keeps no file path, persistent bookmark or saved name. A display name is resolved transiently when possible; an unavailable app can fall back to its chosen identifier.
- Only opt-in preferences and explicitly chosen identifiers persist, including in user-requested settings backups. Current frontmost identity is compared and discarded; only a three-valued result remains in memory. No app use, audio/full-screen history, exact timestamps, content, statistics fields, network capability, entitlement or dependency is added. Import cannot grant permissions.
- English and Turkish settings explain supported scope, unavailable states, selected-list storage and the sharing deferral. Release metadata and documentation for the shipped 2.2.5 product remain unchanged.

## Verification and evidence limits

- All **184 Swift tests in 18 suites** passed locally, retaining the M1–M7 regressions. M8 adds tests for positive/negative/unavailable input aggregation; native full-screen versus menu/Dock hiding; exact foreground selection; opt-in defaults and legacy decoding; bounded/hostile settings; preference persistence without live snapshots; all reminder styles and skip modes; overlapping quiet reasons and typing budgets; grace-period delivery; inactivity, manual pause, Office Hours, sleep/lock, manual rest, preview and pointer-countdown interactions.
- Source/security and tracked publication guards, localization syntax checks, release build and ad hoc signature verification passed locally. These are targeted checks, not an independent security audit. No version was changed and no release was published.
- A disposable signed probe compiled the unchanged M8 monitor/policy source with the same two entitlements as Molaway. It reported readable audio-input state, native presentation state and a valid frontmost identifier. It printed availability booleans only, without identities or content. This establishes query availability in that one environment, not positive detection during a real microphone session or full-screen transition.
- A complete app copy with a separate disposable bundle identity was inspected in English and Turkish. UI automation observed the off defaults and readable layouts, selected and removed the disposable application, and opened both audio/full-screen options without a permission prompt. Status readings were available. This does not establish real foreground-switch suppression, positive audio/full-screen detection, notification delivery, VoiceOver speech or every keyboard path. The installed personal app and its preferences were not replaced.
- Local isolated installation verification stopped at its running-Molaway guard; the personal app was kept running. The PR's normal CI includes the isolated installation checks. CI results must be verified before merging.

Real microphone and virtual-device transitions, other apps' full-screen/foreground changes, stale/unavailable OS readings, meetings, remote sessions, multiple displays/Spaces, accessibility and sustained energy use remain physically unverified. No new physical-test session is required: report daily-use issues and investigate them within the established M6 policy. M8 remains unshipped.
